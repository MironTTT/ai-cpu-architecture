# Замеры производительности

Все числа получены на одной машине, одним и тем же бинарником, без прогрева
системы «на глазок» — методика описана ниже, её можно воспроизвести одной
командой.

---

| | |
|---|---|

| Потоков | 1 (однопоточно, без OpenMP) |

## Методика

1. Генерируются **1000 случайных примеров** (4-значные множители, seed = 42).
2. **Точность** считается одним честным проходом по всем 1000 примерам:
   сравнивается каждая из 8 выходных цифр с эталоном из `int64`-произведения.
   Учитываются две метрики: доля верных цифр и доля примеров, где верны все 8.
3. **Скорость** считается так: батч из 1000 примеров повторяется в цикле, пока
   суммарное время не превысит 250 мс (перед этим — 3 прогревочных прохода).
   `примеров/сек = 1000 × число_повторов / время`.
4. Внутри цикла нет ни одной аллокации: буфер значений и массив выходов
   выделяются один раз и переиспользуются.

Такой подход убирает шум таймера: один проход по 1000 примеров занимает
~0.08 мс, что на пределе разрешения `steady_clock`.

> **Важно:** сравнение условное. Это разные задачи: умножение — чистая

> утверждение: *стоимость одного шага вычисления в графе на 8 порядков ниже*,
> а не «граф умнее модели». Именно это и есть тезис проекта — проверяем его
> дальше на логике и коде.

## Графы, найденные обучением (дифференцируемый граф)

Методика та же, но задача другая: полный перебор таблицы истинности (16 входов),
эталон считается в C++ независимо от Python. Окно измерения — 250 мс.

| Задача | Узлов | Связей | Точность | Бит-в-бит | Примеров/сек | мкс/пример |
|---|---|---|---|---|---|---|
| `parity4` | 7 | 6 | 100% (16/16) | да | ~83.5 млн | 0.012 |
| `add2` | 12 | 16 | 100% (16/16) | да | ~45.6 млн | 0.022 |

Значения — медиана пяти прогонов, разброс меньше 2%.

Время обучения (Python, 1 поток CPU, `torch.set_num_threads(1)`):

| Задача | Конфигурация | Время | Результат градиента |
|---|---|---|---|
| `parity4` | 8 узлов, 3000 шагов, 1 рестарт | 1.22 с | 100% (добивка не нужна) |
| `add2` | 8 узлов, 3000 шагов, 8 рестартов | 99.84 с | 93.75% → добивка → 100% |

> Эти скорости **несопоставимы** с умножением напрямую: графы крошечные, и
> число измеряет в основном стоимость цикла по 16 строкам таблицы истинности.
> Для честного сравнения нужно смотреть на время на узел, а не на абсолют.

`results/diff_graph_cpp.json` — машинночитаемая версия (пишется флагом `--json`).

## Как воспроизвести

```bash
cd src/cpp
powershell -File build.ps1        # или: make
./graph_evolve --json             # 1000 примеров, 250 мс окно, JSON в results/

# другие конфигурации
./graph_evolve --digits 9 --examples 500
./graph_evolve --seed 7 --examples 5000 --time 1000
./graph_evolve --evolve --from-random --pop 32 --gens 15

# графы, обученные в Python (сначала: python -m diffgraph --all из src/python)
./graph_evolve --load ../../results/graphs/parity4.json --load ../../results/graphs/add2.json --json
# или на Windows одной командой:
.\run.ps1 -Graphs
```

## Оговорки

* Числа зависят от CPU и компилятора; на другом железе абсолютные значения
  будут другими, но порядок (десятки наносекунд на пример) сохранится.
* `-march=native` под GCC даёт ещё немного за счёт лучшей раскладки, но
  ядро намеренно не использует интринсики: цель — показать, что обычный
  скалярный целочисленный код на CPU уже решает задачу.
* Замеры энергопотребления пока не проводились — это следующий этап.
